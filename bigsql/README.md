# bigsql: large real-world SQL queries in prela

Seventeen queries of 280–7,200 lines, translated to prela and checked against DuckDB on the same data. The SQL comes from real projects. Where a project builds its result as a chain of models, the chain is inlined as CTEs, so every query here is one self-contained statement.

| set | source | data | queries |
|---|---|---|---|
| mimic | [mimic-code](https://github.com/MIT-LCP/mimic-code) `concepts_duckdb` (ICU severity scores) with every upstream concept inlined | MIMIC-IV Clinical Database Demo 2.2 (100 patients, open, ODbL) | 10 |
| ohdsi | [OHDSI PhenotypeLibrary](https://github.com/OHDSI/PhenotypeLibrary) cohort definitions, rendered to DuckDB by SqlRender, temp tables folded into CTEs | Eunomia GiBleed (OMOP CDM 5.3, synthetic, ~2.7k persons) | 5 |
| tuva | [Tuva](https://github.com/tuva-health/tuva) dbt models, compiled with every upstream model ephemeral | Tuva synthetic claims (small); the NPPES provider registry pruned to the 1,085 NPIs the claims reference | 2 |

eICU was dropped: its only query with joins (`pivoted-oasis`) reads `ventilation_events`, which is not in the public code or data, and has a syntax error.

## Layout

    queries/<set>/<name>.sql      the SQL that is translated (and the oracle source)
    rust/                         cargo workspace
      harness/                    runner, output format, helpers (copied from sqlstorm)
      <set>/src/schema.rs         generated by tools/build_cache.py
      <set>/src/concepts/<m>.rs   one upstream CTE/model each; entry c_<m>
      <set>/src/queries/<q>.rs    the full queries; entry <q>
    tools/                        loaders, inliners, oracle, timing, cache builder
    notes/agent-prompt.md         translation rules and patterns (read before porting)
    notes/audit.md                audit checklist
    timing/{duck,prela}.tsv       timings

Data lives outside the repo in `/Users/paultalma/projects/bigsql_data/<set>/` (`<set>.duckdb`, `cache/`, `oracles/`), plus `src/` (cloned upstream repos) and `venv/` (duckdb, dbt-duckdb).

Each intermediate CTE also has its own oracle (`oracles/c_<m>.txt`), produced by running the query's CTE prefix up to that CTE. So every piece is checked on its own, and the full query is checked end to end. Two exceptions:
- In `tuva/encounters__combined_claim_line_crosswalk`, the SQL's ROW_NUMBER has full ties, and DuckDB itself numbers them differently by thread count. That entry is compared with `claim_line_attribution_number` dropped (`oracles/*.ties`). The final `provider_ranking` is stable at 1–16 threads and is compared in full.
- Many Tuva and some OHDSI CTEs are empty on this data (e.g. the inpatient psych/rehab/hospice encounter types). Those are verified by review against the SQL only. The audit notes say which.

## What prela was missing

Every query was expressible; no port uses host-side joins or filters. The rough edges the porters hit repeatedly:
- **No frame clause on `window`.** `ROWS/RANGE BETWEEN n PRECEDING` is written by hand inside the window closure, or as a self-join plus filter.
- **`Union` can't be probed.** It has to be collected into a `HashIdx` before `.with`/`.select` can use it.
- **No identity relation for a Vec-built relation**, so GROUP BY over derived rows is spelled `rel.map(key).inv().select(rel)`.
- **No owned string type.** Computed strings (`||`, `md5`, `lpad`) are leaked to `&'static str` or kept in a structured form until output.
- **Joins on a range or an OR condition** become `.cross` plus `.filt`.
- **`lag`/`lead` return only the sort column.** LAG of another column needs a custom window closure.
